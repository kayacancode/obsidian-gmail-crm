Local relationship graph queries for agents.

PeopleGraph is a Rust CLI that reads the Gmail CRM plugin's local contact-index.json and emits predictable JSON for agents. It does not start Obsidian, call Gmail, send vault data to a network, or mutate plugin data except for explicit merge-review commands.

Architecture

The plugin remains the source of truth. PeopleGraph is a fast, local adapter over the plugin's structured cache. When Botwick hosts the source-of-truth cache, PeopleGraph can also serve read-only commands over a token-protected HTTP endpoint.

Obsidian Gmail CRM Gmail metadata sync, contact cache, relationship scoring, people-page updates.
contact-index.json Local JSON cache under .obsidian/plugins/gmail-crm/.
peoplegraph Rust CLI reads the cache, returns JSON primitives for agents, or hosts read-only query routes.

Command Surface

Example

peoplegraph --cache /path/to/contact-index.json who-knows --company Disney --format jsonl

Remote Query Mode

This is the first step toward letting anyone query Botwick's graph without installing Obsidian or having the vault locally. The server reads Botwick's contact-index.json and exposes only read-only commands to clients that know the shared bearer token. 

# Server on the source-of-truth machine
export PEOPLEGRAPH_TOKEN="use-a-long-random-token"
peoplegraph --cache /path/to/contact-index.json serve --bind 127.0.0.1:8787

# Client query
peoplegraph --host http://127.0.0.1:8787 --token "$PEOPLEGRAPH_TOKEN" who-knows --company Disney
Remote read-only commands

describe, version, find-person, score, who-knows, get-neighbors, get-edges, suggest-duplicates, and merge-queue.

Local-only writes

propose-merge, dismiss-merge, and apply-merge do not run through --host in V1. Merge review stays explicit on the source-of-truth machine.

Keep the default localhost binding when Botwick calls it on the same host. For other clients, prefer a trusted private network, SSH tunnel, or reverse proxy instead of exposing raw HTTP to the public internet.

Obsidian Visibility

Merge writes land in contact-index.json first. The plugin mirrors canonical_id, aliases, and last_canonical_sync into people-page frontmatter during Gmail CRM: Update staleness scores. The CRM Base now includes visible Canonical ID and Aliases columns.

Gmail CRM: Review merge queue writes People pages/_Merge Queue.md with queue size, pending candidates, applied candidates, dismissed candidates, source cache paths, and copyable apply/dismiss/reopen commands.

Cache Contract

The CLI deserializes the current ContactIndex shape from src/types.ts. Unknown fields are ignored, and optional future fields are accepted when present.

Cache resolution order
  1. --cache <path>
  2. PEOPLEGRAPH_CACHE
  3. Nearest .obsidian/plugins/gmail-crm/contact-index.json
  4. Nearest local contact-index.json
Score behavior

If cached score fields exist, PeopleGraph returns them as score_source: "cached". With today's plugin cache, it gets cached values after staleness updates. Older caches still derive estimates from metadata and return score_source: "estimated_from_metadata".

Implementation Notes

  • Language: Rust 2024 edition.
  • CLI parsing: clap.
  • JSON parsing and output: serde and serde_json.
  • Fuzzy name search: strsim::jaro_winkler.
  • Remote client: ureq.
  • Remote server: standard-library TCP listener with a narrow GET-only JSON API.
  • Release binary after local build: crates/peoplegraph/target/release/peoplegraph.
  • Homebrew install: brew tap kayacancode/tap, then brew install peoplegraph.

The current scoring fallback mirrors the plugin's metadata intent: depth comes from thread depth and back-and-forth counts, recency comes from lastContact, and combined score blends strength with momentum.
