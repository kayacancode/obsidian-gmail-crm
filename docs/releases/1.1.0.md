# People Data Sync 1.1.0

Connects Granola meeting notes to your people pages and adds a pre-meeting brief. Both read the frontmatter written by Granola Sync 3.1.0 or later (`attendee_emails`, `calendar_event_title`, `calendar_start`); run its **Add attendee and calendar fields to existing notes** command once for notes synced earlier.

## Granola meetings on people pages

- Each Granola note is matched to the calendar meeting with the same start time and event title, and takes that meeting's attendees. Granola usually lists only the note's owner, so this is what finds the other people. When there's no calendar match, the note's attendee emails are used. Display names and transcript speaker labels are never matched.
- People pages get a plugin-managed `## Granola meetings` section, newest first, rebuilt on each run and removed when empty. Granola notes are never written, and no pages are created.
- Meetings matched to a calendar event aren't counted twice; meetings found only through attendee emails count toward relationship history, and a calendar sync keeps them.
- Runs after each sync, when a Granola note's frontmatter changes, and from the **Link Granola meetings to people** command.

## Pre-meeting brief

- One plugin-owned note, `Pre-meeting brief.md` (path in settings), covering your meetings in the next 7 days, rebuilt after each sync and by the **Open pre-meeting brief** command.
- For each meeting: the open next steps from the most recent earlier Granola note about the same meeting (the same calendar title, the same series title, so "Alex + Sam weekly" matches "Alex & Sam", or the same attendees), then each attendee with their people page, last contact and nudge.
- Next steps that name someone other than you are left out, and meetings with no related note show none rather than unrelated ones. Meeting times are labelled with their time zone, and meetings invited through a shared calendar are kept.

Gmail sync, scoring, saved data and the signed release process are unchanged.
