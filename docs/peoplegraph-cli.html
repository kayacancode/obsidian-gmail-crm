PeopleGraph CLI PRD

A single-binary Rust CLI that exposes the Obsidian Gmail CRM plugin's contact data to agents through stable JSON graph primitives.

Status: Draft v0.3 Owner: Kaya Updated: 2026-05-22

Summary

peoplegraph reads the plugin's local contact-index.json cache directly and can also serve read-only queries from that cache over a token-protected HTTP endpoint. Local use does not need Obsidian running; remote use needs a bearer token. Botwick is the source-of-truth consumer, but the command surface is general enough for other agents.

For a copy/paste starter page for remote users, see PeopleGraph Remote Query Guide.

Current implementation: the CLI implements describe, version, find-person, score, who-knows, get-neighbors, get-edges, contact-card, import-cache, suggest-external-merges, apply-external-merge, dismiss-external-merge, suggest-duplicates, merge-queue, apply-merge, dismiss-merge, propose-merge, and read-only serve. The plugin writes schemaVersion, contact score snapshots, relationship edges, and canonical identity metadata into contact-index.json during staleness updates.

Problem

Botwick can read the Obsidian vault, but markdown is a brittle query surface for questions like "who do we know at Disney?" The plugin already computes contacts, scores, dedup signals, and relationship edges. PeopleGraph exposes that structured data in an agent-shaped format.

Users And Consumers

  • Botwick: primary OpenClaw agent on the Mac mini.
  • Jordan's Hermes agent: secondary consumer.
  • Future agents: any system that needs scored relationship data.

Humans continue using the Obsidian sidebar, Base views, and quadrant views. PeopleGraph is JSON on stdout, with no prompts or color output.

Goals

  1. Implement graph primitives as standalone CLI commands.
  2. Emit stable JSON or JSONL for agent parsing.
  3. Ship as a single release binary with sub-100ms cold-start target.
  4. Keep read-only commands non-mutating; reserve writes for explicit merge commands.
  5. Support who-knows --company X as a compound query.
  6. Let approved clients query Botwick's source-of-truth cache without installing Obsidian.

Non-Goals

  • Writing directly to Jon's shared graph endpoint.
  • Replacing the plugin's TypeScript scoring as source of truth.
  • Bulk-editing vault notes from the CLI.
  • Conversation-content analysis.
  • Replacing human-facing Obsidian UI.

Architecture

Obsidian plugin (TS)
  Gmail sync -> scoring -> quadrant
  Writes contact-index.json and message-cache.json
        |
        v
peoplegraph (Rust)
  Loads contact-index.json on each invocation
  Emits JSON locally or serves read-only HTTP
        |
        v
Agent consumer, primarily Botwick

The Rust binary depends on the JSON shape in src/types.ts. ContactIndex.schemaVersion gives forward-compatibility for future schema changes.

Obsidian Visibility

apply-merge updates the plugin cache first. The plugin then mirrors canonical identity into people-page frontmatter during Gmail CRM: Update staleness scores, which makes canonical_id and aliases visible in the CRM Base view.

Gmail CRM: Review merge queue writes and opens People pages/_Merge Queue.md with pending, applied, and dismissed merge candidates. Pending rows include both apply and dismiss commands, so reviewed merges are visible in the vault instead of only in JSON.

CLI Surface

peoplegraph find-person <query>
peoplegraph get-neighbors <email>
peoplegraph get-edges --from <a> --to <b>
peoplegraph score <email>
peoplegraph who-knows --company <name>
peoplegraph contact-card <email-or-name>
peoplegraph import-cache --source <source> /path/to/contact-index.json
peoplegraph suggest-external-merges --source <source> --limit 25
peoplegraph apply-external-merge --source <source> --primary <email> --external <email>
peoplegraph dismiss-external-merge --source <source> --primary <email> --external <email> --reason not_same_person
peoplegraph suggest-duplicates --limit 25 --min-confidence 0.82
peoplegraph merge-queue --status pending --limit 25
peoplegraph apply-merge <a> <b>
peoplegraph dismiss-merge <a> <b> --reason not_duplicate
peoplegraph propose-merge <a> <b>
peoplegraph describe
peoplegraph version
peoplegraph --cache /path/to/contact-index.json serve --bind 127.0.0.1:8787

Global flags: --format json|jsonl, --cache <path>, --host <url>, --token <value>, and --quiet.

Remote Query Mode

Botwick can host the universal source-of-truth contact-index.json and expose only read-only query commands to approved clients.

# On Botwick's machine
export PEOPLEGRAPH_TOKEN="use-a-long-random-token"
peoplegraph --cache /path/to/contact-index.json serve --bind 127.0.0.1:8787

# From a client
peoplegraph --host http://127.0.0.1:8787 --token "$PEOPLEGRAPH_TOKEN" who-knows --company Disney

Supported remotely: describe, version, find-person, score, who-knows, get-neighbors, get-edges, contact-card, suggest-duplicates, suggest-external-merges, and merge-queue. Write commands are intentionally local-only in V1: import-cache, apply-external-merge, dismiss-external-merge, propose-merge, dismiss-merge, and apply-merge.

Default binding is localhost. For another person or machine, put this behind a trusted private network, SSH tunnel, or reverse proxy rather than exposing raw HTTP on the public internet.

Identity And Dedup

  • Primary key is lowercased email.
  • aliases are deterministic match keys.
  • Name matching falls back to Levenshtein-style similarity through strsim.
  • suggest-duplicates skips pairs already present in merge-queue.json.
  • propose-merge writes local pending candidates to merge-queue.json.
  • dismiss-merge marks a candidate dismissed, preserving the reason so it does not keep reappearing.
  • apply-merge writes matching canonicalId, aliases, and lastCanonicalSync to contact-index.json and marks the queue item applied.

External Source Staging

import-cache stages another Gmail CRM plugin user's contact-index.json in external-sources.json next to Botwick's source-of-truth cache. It never overwrites the main graph during import.

contact-card returns a minimal shared core card plus source-specific evidence. The shared core card is objective identity data; private relationship context remains source-specific.

apply-external-merge only merges objective identity fields, currently aliases/emails and missing company or role fields. dismiss-external-merge records false positives so they stop reappearing.

John's OpenClaw Telegram agent can review these suggestions through inline Merge, Reject, and Details buttons. See PeopleGraph Telegram Merge Review.
